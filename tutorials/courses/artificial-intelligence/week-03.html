Week 3: Adversarial Search & Game Playing

In Week 2 the world sat still while the agent searched. In games, an opponent is actively working against you. This week covers the algorithms behind decades of game-playing AI — from minimax and alpha-beta pruning, which powered Deep Blue, to Monte Carlo Tree Search, which powered AlphaGo.

Phase 1 of 6 Week 3 of 19 ~3–4 Hours Hands-on Exercise Included

By the end of this week, you'll be able to

  • Model two-player games as game trees and solve them with minimax
  • Speed up minimax with alpha-beta pruning and move ordering
  • Use evaluation functions and Monte Carlo Tree Search for large games

1. Games as Search Problems

A two-player, zero-sum, perfect-information game — chess, tic-tac-toe, Connect Four — is defined by an initial state, whose turn it is, legal moves, a result function, a terminal test, and a utility for terminal states (e.g. +1 win, 0 draw, −1 loss for MAX). Players alternate: MAX tries to maximize the utility, MIN to minimize it.

The resulting game tree is enormous. Tic-tac-toe has fewer than 9! = 362,880 move sequences; chess has around 1040 legal positions. Solving small games exactly and approximating large ones is the theme of this week.

2. Minimax

Minimax assumes both players play optimally. The value of a position is its utility if terminal; otherwise the maximum (MAX's turn) or minimum (MIN's turn) of its children's values.

tictactoe_minimax.py
LINES = [(0,1,2),(3,4,5),(6,7,8),(0,3,6),(1,4,7),(2,5,8),(0,4,8),(2,4,6)]

def winner(board):
    for a, b, c in LINES:
        if board[a] and board[a] == board[b] == board[c]:
            return board[a]
    return None

def minimax(board, player):
    w = winner(board)
    if w == "X": return 1
    if w == "O": return -1
    if all(board): return 0                                   # draw
    values = []
    for i in range(9):
        if not board[i]:
            board[i] = player
            values.append(minimax(board, "O" if player == "X" else "X"))
            board[i] = None                                   # undo move
    return max(values) if player == "X" else min(values)

def best_move(board, player):
    moves = [i for i in range(9) if not board[i]]
    def score(i):
        board[i] = player
        v = minimax(board, "O" if player == "X" else "X")
        board[i] = None
        return v
    return max(moves, key=score) if player == "X" else min(moves, key=score)

Run minimax([None]*9, "X") and you get 0: perfect play from both sides is always a draw.

3. Alpha-Beta Pruning

Minimax explores branches that can't possibly change the decision. Alpha-beta tracks two bounds: α, the best value MAX can already guarantee, and β, the best MIN can guarantee. When α ≥ β, the rest of that branch is irrelevant and is skipped.

alphabeta.py
def alphabeta(board, player, alpha=-2, beta=2):
    w = winner(board)
    if w == "X": return 1
    if w == "O": return -1
    if all(board): return 0
    if player == "X":
        value = -2
        for i in range(9):
            if not board[i]:
                board[i] = "X"
                value = max(value, alphabeta(board, "O", alpha, beta))
                board[i] = None
                alpha = max(alpha, value)
                if alpha >= beta:
                    break                    # MIN will never allow this line
        return value
    else:
        value = 2
        for i in range(9):
            if not board[i]:
                board[i] = "O"
                value = min(value, alphabeta(board, "X", alpha, beta))
                board[i] = None
                beta = min(beta, value)
                if alpha >= beta:
                    break
        return value

Alpha-beta returns exactly the same value as minimax. With good move ordering (best moves first) it examines roughly O(bd/2) nodes instead of O(bd) — effectively doubling the depth you can search in the same time.

Ordering moves well

Engines try captures and checks first, reuse the best move from a shallower search (iterative deepening), and remember "killer moves" that caused cutoffs elsewhere. Better ordering means more pruning.

4. Evaluation Functions & Monte Carlo Tree Search

For big games you can't search to the end. Instead, cut off at a fixed depth and apply an evaluation function — a heuristic estimate of who's winning. Classic chess engines used weighted features: material (queen = 9, rook = 5…), mobility, king safety, pawn structure.

Monte Carlo Tree Search needs no hand-written evaluation function. It grows a search tree by repeating four steps:

  1. Selection — walk down the tree choosing children by the UCB1 score, balancing high win rate (exploitation) with few visits (exploration).
  2. Expansion — add one new child node.
  3. Simulation — play random moves from there to the end of the game.
  4. Backpropagation — update win/visit counts along the path.
ucb1.py
import math

def ucb1(child_wins, child_visits, parent_visits, c=1.41):
    if child_visits == 0:
        return float("inf")                     # always try unvisited moves
    exploit = child_wins / child_visits
    explore = c * math.sqrt(math.log(parent_visits) / child_visits)
    return exploit + explore

AlphaGo replaced random simulations with neural networks: a policy network suggests promising moves and a value network evaluates positions. That pairing of search with learned intuition reappears in Week 7 (reinforcement learning) and in modern LLM reasoning systems that search over candidate solutions.

5. Hands-on Exercise

Hands-on

Build an unbeatable tic-tac-toe player and a Connect Four bot

  1. Write a playable tic-tac-toe game in the terminal where the computer uses best_move. Confirm you can't beat it.
  2. Count nodes visited by minimax vs alpha-beta from the empty board.
  3. Implement Connect Four (7×6) with depth-limited alpha-beta (depth 5) and an evaluation function that scores open lines of two and three.
  4. Implement MCTS for Connect Four with 2,000 iterations per move. Play 20 games of alpha-beta vs MCTS and report the results.
Hint

Add memoization to tic-tac-toe minimax with a dictionary keyed on (tuple(board), player). Many move orders reach the same position, so this cuts the work dramatically — the same idea as a chess engine's transposition table.

6. Knowledge Check

4 quick questions. Expand each to check your answer.

Q1

What assumption does minimax make about the opponent?

That the opponent plays optimally — always choosing the move that's worst for you. Against a weaker opponent minimax is still safe, though it may miss chances to exploit their mistakes.

Q2

Does alpha-beta pruning ever change the result compared with minimax?

No. It returns the same value and the same best move; it only skips branches that provably cannot affect the decision.

Q3

Why does move ordering matter for alpha-beta?

Cutoffs happen when a good move is found early. If the best moves are examined first, the bounds tighten quickly and many more branches are pruned, approaching O(bd/2) nodes.

Q4

What problem does the exploration term in UCB1 solve?

Without it, MCTS would keep choosing whichever move looked best after a few random games and never discover moves that were unlucky early on. The exploration term boosts rarely visited moves so every option gets tested enough.
