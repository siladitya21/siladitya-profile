Chapter 2: File Handling in Python

Based on NCERT's Class XII Computer Science textbook. Everything a program holds in memory disappears the moment it stops running — this chapter covers how to make data outlive the program by storing it in text and binary files: opening and closing files, the write()/writelines() and read()/readline()/readlines() methods, moving around a file with seek() and tell(), and serializing whole Python objects with the pickle module.

By the end of this chapter, you'll be able to

  • Open a text file in the right mode, write to it, and read it back three different ways
  • Move the file object around with seek() and tell() for random access
  • Pickle and unpickle a Python object to and from a binary file

2.1–2.2 Introduction & Types of Files

Variables in a program only live as long as the program is running. To store input and output permanently, so it can be reused without re-entering it, we need a file — a named location on a secondary storage media where data are permanently stored for later access.

Every file on disk is ultimately just a series of bytes. Python works with two broad kinds:

  • Text files — human-readable characters (.txt, .py, .csv, .html). Each byte is the ASCII/Unicode value of one character, and each line ends with an End of Line (EOL) character — \n by default in Python.
  • Binary files — bytes that represent actual content (images, audio, executables) rather than character codes. They aren't human-readable and need specific software to open; even a single flipped bit can corrupt one.
NCERT Activity 2.1

Save your name in Notepad as a .txt file, then in Word as a .docx file. The .txt file's size is in bytes; the .docx is in KBs — because a .docx also stores author name, page settings, fonts and edit history, while a text file stores only the ASCII equivalent of the characters themselves.

2.3 Opening and Closing a Text File

2.3.1 Opening a file — open()

syntax
file_object = open(file_name, access_mode)

This returns a file object (file handle) used for every later read/write call. If the file doesn't exist, Python creates a new empty one with that name. Three useful attributes: file.closed, file.mode and file.name.

Table 2.1 — file open modes
r          read-only                        offset: beginning of file
rb         binary, read-only                offset: beginning of file
r+ / +r    read and write                   offset: beginning of file
w          write (overwrites if exists, else creates new) offset: beginning
wb+ / +wb  read, write & binary (overwrites or creates new) offset: beginning
a          append (creates new if missing)  offset: end of file
a+ / +a    append and read (creates new if missing) offset: end of file
Python shell
myObject = open("myfile.txt", "a+")
# opened in append + read mode -- file object starts at the END of the file

2.3.2 Closing a file — close()

syntax
file_object.close()

Closing frees the memory allocated to the file and flushes any unwritten data from the buffer to the file on disk — always close a file once you're done with it.

2.3.3 Opening a file using with

syntax
with open(file_name, access_mode) as file_object:
    # work with file_object here

A file opened via with is closed automatically once control leaves the block — even if the user forgets close(), or an exception occurs partway through.

Python shell
with open("myfile.txt", "r+") as myObject:
    content = myObject.read()
# myObject is already closed here -- no explicit close() needed

2.4 Writing to a Text File

To write, open the file in write (w) or append (a) mode. Write mode erases any existing content first; append mode adds after it.

2.4.1 write()

Takes a single string and writes it, returning the number of characters written. You must add \n yourself to end a line.

Python shell
>>> myobject = open("myfile.txt", 'w')
>>> myobject.write("Hey I have started using files in Python\n")
41
>>> myobject.close()

Numeric data must be converted to a string first, e.g. myobject.write(str(marks)). Internally, write() fills a buffer; close() (or flush()) is what actually moves that buffer's contents onto permanent storage.

2.4.2 writelines()

Writes an iterable of strings (list/tuple) in one call. Unlike write(), it does not return a character count.

Python shell
>>> myobject = open("myfile.txt", 'w')
>>> lines = ["Hello everyone\n", "Writing multiline strings\n", "This is the third line"]
>>> myobject.writelines(lines)
>>> myobject.close()

2.5 Reading from a Text File

The file must be opened in r, r+, w+ or a+ mode first. Three methods:

2.5.1 read(n)

Python shell
>>> myobject = open("myfile.txt", 'r')
>>> myobject.read(10)
'Hello ever'
>>> myobject.close()

>>> myobject = open("myfile.txt", 'r')
>>> print(myobject.read())    # no argument (or negative) reads the whole file
Hello everyone
Writing multiline strings
This is the third line

2.5.2 readline([n])

Reads one line, up to and including the \n. With n given, it reads at most n bytes, never crossing past the newline. Returns an empty string at end-of-file — the common way to loop over a file line by line.

Python shell
>>> myobject = open("myfile.txt", 'r')
>>> myobject.readline(10)
'Hello ever'

>>> myobject = open("myfile.txt", 'r')
>>> print(myobject.readline())
'Hello everyone\n'

2.5.3 readlines()

Reads every line into a list of strings, each ending with \n.

Python shell
>>> myobject = open("myfile.txt", 'r')
>>> print(myobject.readlines())
['Hello everyone\n', 'Writing multiline strings\n', 'This is the third line']

>>> d = myobject.readlines()
>>> for line in d:
...     print(line.split())        # splits each line into a list of words
['Hello', 'everyone']
['Writing', 'multiline', 'strings']
['This', 'is', 'the', 'third', 'line']

>>> for line in d:
...     print(line.splitlines())   # splitlines() keeps each whole line as one element
['Hello everyone']
['Writing multiline strings']
['This is the third line']
Program 2-1 — write, then read back
fobject = open("testfile.txt", "w")
sentence = input("Enter the contents to be written in the file: ")
fobject.write(sentence)
fobject.close()

print("Now reading the contents of the file: ")
fobject = open("testfile.txt", "r")
for str in fobject:      # looping over the file object itself
    print(str)
fobject.close()

2.6 Setting Offsets in a File — seek() & tell()

The methods above read sequentially. For random access, Python gives us two more:

syntax
file_object.tell()                              # current byte position
file_object.seek(offset[, reference_point])     # move to a byte position

# reference_point: 0 = beginning (default), 1 = current position, 2 = end of file
Program 2-2 — application of seek() and tell()
fileobject = open("testfile.txt", "r+")
str = fileobject.read()
print(str)
print("Initial position:", fileobject.tell())

fileobject.seek(0)
print("Back at beginning:", fileobject.tell())

fileobject.seek(10)
print("Moved to byte 10:", fileobject.tell())
str = fileobject.read()
print(str)

With a file holding roll_numbers = [1, 2, 3, 4, 5, 6] (33 bytes), tell() reports 33 after reading it all; seek(0) resets to 0; seek(10) jumps to byte 10, and reading from there returns rs = [1, 2, 3, 4, 5, 6] — everything from the 11th character onward.

2.7 Creating and Traversing a Text File

Program 2-3 — create a file and write data
fileobject = open("practice.txt", "w+")
while True:
    data = input("Enter data to save in the text file: ")
    fileobject.write(data)
    ans = input("Do you wish to enter more data?(y/n): ")
    if ans == 'n':
        break
fileobject.close()
Program 2-4 — traverse and display, line by line
fileobject = open("practice.txt", "r")
str = fileobject.readline()
while str:
    print(str)
    str = fileobject.readline()   # returns "" at end-of-file, ending the loop
fileobject.close()

Program 2-5 in the textbook combines both into one w+ file object: it writes several sentences, calls fileobject.tell() to report the byte position reached, then fileobject.seek(0) to rewind to the start before reading everything back with read() — all through the same file handle.

2.8 The Pickle Module

Everything in Python — lists, tuples, dictionaries, any object — can be saved to a binary file exactly as it is, using the pickle module. Serialization (also called pickling) converts an in-memory object into a stream of bytes that can be stored in a file; deserialization (unpickling) reverses it. With pickle, data is dumped, not written, and loaded, not read — always against a file opened in binary mode (wb / rb).

2.8.1 dump()

syntax
pickle.dump(data_object, file_object)
Program 2-6 — pickling data
import pickle
listvalues = [1, "Geetika", 'F', 26]
fileobject = open("mybinary.dat", "wb")
pickle.dump(listvalues, fileobject)
fileobject.close()

2.8.2 load()

syntax
store_object = pickle.load(file_object)
Program 2-7 — unpickling data
import pickle
fileobject = open("mybinary.dat", "rb")
objectvar = pickle.load(fileobject)
fileobject.close()
print(objectvar)
# [1, 'Geetika', 'F', 26]

2.8.3 File handling with pickle — records in a loop

The textbook's full example appends employee records ([eno, ename, ebasic, allow, totsal]) one at a time to a binary file, then reads them back by calling pickle.load() repeatedly inside a loop — catching EOFError to know when the file has been fully read:

Program 2-8 — reading records until EOFError
import pickle

readrec = 1
try:
    with open("empfile.dat", "rb") as bfile:
        while True:
            edata = pickle.load(bfile)
            print("Record Number:", readrec)
            print(edata)
            readrec = readrec + 1
except EOFError:
    pass
Why except EOFError?

Unlike readline() on a text file, pickle.load() has no "empty string" signal for end-of-file — it raises EOFError instead once there's nothing left to unpickle. This ties directly back to Chapter 1's exception handling.
