3.1–3.2 Introduction & Stack

A data structure defines a mechanism to store, organise and access data along with the operations that can be efficiently performed on it — string and list from Class XI are examples. Stack and Queue are two more, and although Python has no dedicated stack type, they're used constantly across programming languages.

Think of a pile of plates or a pile of books: you always add a new one on top, and always remove the top one first. That's a stack — elements are added and removed from one end only, called the TOP, following the Last-In-First-Out (LIFO) principle: the most recently inserted element is the first one taken out.

Real-life & programming applications

Bangles on a wrist, a pile of boxes in a pantry — and in software: reversing a string, a text editor's undo/redo, a browser's BACK button history, and checking that parentheses in an expression are properly matched and nested.

3.3 Operations on Stack

  • PUSH — inserts a new element at the TOP. Trying to push onto a full stack is overflow.
  • POP — removes the element at the TOP. Trying to pop an empty stack is underflow.

Picture a stack of numbered glasses: PUSH 1, PUSH 2, POP (removes 2), PUSH 3, PUSH 4, then POP four times in a row — each POP removes whatever was pushed most recently (4, then 3, then 1 — remember 2 was already removed), until the stack is empty again.

3.4 Implementation of Stack in Python

The simplest way to implement a stack in Python is with a list, fixing one end as TOP. Using append() for PUSH and pop() for POP — both of which act on the rightmost end of the list — means no explicit TOP index is ever needed. Because Python lists have no fixed size, this stack never actually overflows (barring running out of memory).

Stack functions built on a Python list
glassStack = list()   # create an empty stack

def isEmpty(glassStack):
    if len(glassStack) == 0:
        return True
    else:
        return False

def opPush(glassStack, element):
    glassStack.append(element)

def size(glassStack):
    return len(glassStack)

def top(glassStack):
    if isEmpty(glassStack):
        print('Stack is empty')
        return None
    else:
        x = len(glassStack)
        return glassStack[x-1]

def opPop(glassStack):
    if isEmpty(glassStack):
        print('underflow')
        return None
    else:
        return glassStack.pop()

def display(glassStack):
    x = len(glassStack)
    print("Current elements in the stack are: ")
    for i in range(x-1, -1, -1):
        print(glassStack[i])
Using the stack
glassStack = list()

opPush(glassStack, 'glass1')
opPush(glassStack, 'glass2')
print("Current number of elements in stack is", size(glassStack))

element = opPop(glassStack)        # removes 'glass2'
opPush(glassStack, 'glass3')
print("top element is", top(glassStack))   # 'glass3'
display(glassStack)                # glass3, glass1 (top to bottom)

while True:
    item = opPop(glassStack)
    if item == None:
        print("Stack is empty now")
        break
    else:
        print("Popped element is", item)

3.5 Notations for Arithmetic Expressions

Any arithmetic expression can be written three ways:

Table 3.1 — Infix, Prefix, Postfix
Infix   (operator BETWEEN operands, needs BODMAS + parentheses)
        x * y + z        3 * (4 + 5)      (x + y) / (z * 5)

Prefix  (Polish notation — operator BEFORE its operands)
        + z * x y        * 3 + 4 5        / + x y * z 5

Postfix (Reverse Polish — operator AFTER its operands)
        x y * z +        3 4 5 + *        x y + z 5 * /

Prefix/postfix need no parentheses and no precedence rules at evaluation time — the position of each operator already encodes the order of evaluation, so a single left-to-right pass is enough.

3.6 Conversion from Infix to Postfix Notation

A stack tracks operators and parentheses encountered while scanning the infix expression left to right; a string accumulates the postfix result.

Algorithm 3.1
1. Create an empty string postExp.
2. INPUT infix expression inExp.
3. For each character in inExp:
     IF character is '('       → PUSH it on the Stack
     ELSE IF character is ')'  → POP from Stack and append to postExp
                                  until the matching '(' is popped
                                  (discard both parentheses)
     ELSE IF character is an operator:
         IF its precedence <= operator at top of Stack
             → POP operators (append each to postExp) until one
               of lower precedence is found, THEN push this operator
         ELSE → PUSH this operator on the Stack
     ELSE (it's an operand)    → append it directly to postExp
4. After the last character, POP all remaining Stack elements
   and append them to postExp.
5. OUTPUT postExp.

Example 3.1 — converting (x + y)/(z*8):

Step-by-step trace
Symbol:  (    x    +    y    )    /    (    z    *    8    )   [end]
Stack:   (    (   +(   +(    /         /(   /(  */(  */(   /       empty
postExp: ""   x    x   xy   xy+  xy+  xy+ xy+z xy+z xy+z8 xy+z8* xy+z8*/

Result: x y + z 8 * / — operators are the only things ever pushed during this conversion.

3.7 Evaluation of Postfix Expression

Algorithm 3.2
1. INPUT postfix expression postExp.
2. For each character in postExp:
     IF it's an operand → PUSH it on the Stack
     ELSE (it's an operator)
          → POP two elements, apply the operator to them,
            PUSH the computed result back onto the Stack
3. When input is exhausted, the Stack should hold exactly one
   element: POP it — that's the final result.
   (More than one element left means an invalid expression.)

Example 3.2 — evaluating 7 8 2 * 4 / +:

Step-by-step trace
Symbol:  7    8    2    *          4    /         +
Action:  PUSH PUSH PUSH POP 8,2;   PUSH POP 16,4;  POP 7,4;
                         8*2=16;        16/4=4;    4+7=11
                         PUSH 16                    PUSH 11
Stack:   [7]  [7,8][7,8,2] [7,16] [7,16,4] [7,4]    [11]

Final result: 11. Note this algorithm only ever pushes operands onto the stack — the mirror image of the infix→postfix conversion, which only ever pushes operators.
