Chapter 9: Structured Query Language (SQL)

Based on NCERT's Class XII Computer Science textbook — the highest-weightage chapter for the practical exam. Using MySQL and the StudentAttendance database from Chapter 8, this chapter covers data types and constraints, DDL (CREATE, ALTER, DROP), DML (INSERT, UPDATE, DELETE), the full SELECT query toolkit, built-in functions, GROUP BY/HAVING, set operations, and joining two tables.

By the end of this chapter, you'll be able to

  • Create, alter and populate tables with the right data types and constraints
  • Write SELECT queries using WHERE, ORDER BY, LIKE, IN, BETWEEN and NULL checks
  • Use single-row and aggregate functions, GROUP BY/HAVING, and JOIN two tables

9.1–9.3 SQL Basics, Data Types & Constraints

SQL (Structured Query Language) is the most popular query language for RDBMS like MySQL, Oracle and SQL Server. It's case-insensitive, statements end with a semicolon, and unfinished multi-line statements continue at the -> prompt. Beyond querying, SQL also defines structure, manipulates data and declares constraints.

Common MySQL data types
CHAR(n)      fixed-length string, 0-255 chars (pads with spaces)
VARCHAR(n)   variable-length string, 0-65535 chars (uses only what's needed)
INT          integer, 4 bytes (0 to 4,294,967,295 unsigned) -- BIGINT for larger
FLOAT        decimal number, 4 bytes
DATE         'YYYY-MM-DD', range '1000-01-01' to '9999-12-31'
Common SQL constraints
NOT NULL      column cannot have NULL (missing/unknown) values
UNIQUE        all values in the column must be distinct
DEFAULT       value used when none is provided
PRIMARY KEY   uniquely identifies each row (implies NOT NULL + UNIQUE)
FOREIGN KEY   references a PRIMARY KEY column in another table

9.4 SQL for Data Definition (DDL)

CREATE DATABASE, USE, SHOW
CREATE DATABASE StudentAttendance;
USE StudentAttendance;
SHOW DATABASES;
SHOW TABLES;
CREATE TABLE
CREATE TABLE STUDENT(
    RollNumber INT,
    SName VARCHAR(20),
    SDateofBirth DATE,
    GUID CHAR(12),
    PRIMARY KEY (RollNumber));

DESCRIBE STUDENT;     -- or DESC STUDENT; shows the table's structure
ALTER TABLE — the nine common operations
-- (A) Add primary key
ALTER TABLE GUARDIAN ADD PRIMARY KEY (GUID);
-- composite primary key:
ALTER TABLE ATTENDANCE ADD PRIMARY KEY(AttendanceDate, RollNumber);

-- (B) Add foreign key (referenced table/column must already exist,
--     and be a primary key there)
ALTER TABLE STUDENT ADD FOREIGN KEY(GUID) REFERENCES GUARDIAN(GUID);

-- (C) Add UNIQUE constraint to an existing column
ALTER TABLE GUARDIAN ADD UNIQUE(GPhone);

-- (D) Add a new column
ALTER TABLE GUARDIAN ADD income INT;

-- (E) Modify a column's data type
ALTER TABLE GUARDIAN MODIFY GAddress VARCHAR(40);

-- (F) Modify a column's constraint (NULL -> NOT NULL)
ALTER TABLE STUDENT MODIFY SName VARCHAR(20) NOT NULL;

-- (G) Add a default value
ALTER TABLE STUDENT MODIFY SDateofBirth DATE DEFAULT '2000-05-15';

-- (H) Remove a column
ALTER TABLE GUARDIAN DROP income;

-- (I) Remove the primary key
ALTER TABLE GUARDIAN DROP PRIMARY KEY;
DROP — irreversible, use with care
DROP TABLE table_name;
DROP DATABASE database_name;   -- removes ALL tables inside it too

9.5 SQL for Data Manipulation (DML — Insert)

INSERT INTO — all values, in column order
INSERT INTO GUARDIAN
VALUES (444444444444, 'Amit Ahuja', 5711492685, 'G-35, Ashok Vihar, Delhi');
INSERT INTO — naming specific columns (others get NULL/default)
INSERT INTO GUARDIAN (GUID, GName, GAddress)
VALUES (333333333333, 'Danny Dsouza', 'S-13, Ashok Village, Daman');
-- GPhone is left NULL since it wasn't specified

INSERT INTO STUDENT VALUES (3, 'Taleem Shah', '2002-02-28', NULL);
-- explicit NULL works too, but ONLY if you list a value for every column
Insert order matters

Always populate a referenced table (e.g. GUARDIAN) before the table that holds a foreign key to it (e.g. STUDENT) — otherwise the foreign key check fails.

9.6 SQL for Data Query — the SELECT statement

Basic syntax
SELECT attribute1, attribute2, ...
FROM table_name
WHERE condition;        -- optional

SELECT * FROM table_name;   -- all columns
(B) Renaming columns with AS (alias)
SELECT EName AS Name, Salary*12 AS 'Annual Income' FROM EMPLOYEE;
-- Note: a space in the alias needs quotes. The alias never changes the actual table.
(C) DISTINCT — remove duplicate rows
SELECT DISTINCT DeptId FROM EMPLOYEE;
(D) WHERE — relational & logical operators
SELECT * FROM EMPLOYEE WHERE Salary > 5000 AND DeptId = 'D04';
SELECT * FROM EMPLOYEE WHERE NOT Ename = 'Aaliya';
SELECT Ename, DeptId FROM EMPLOYEE WHERE Salary >= 20000 AND Salary <= 50000;
-- operators: =  !=  <  <=  >  >=      logical: AND  OR  NOT
BETWEEN — inclusive range (equivalent to the AND query above)
SELECT Ename, DeptId FROM EMPLOYEE WHERE Salary BETWEEN 20000 AND 50000;
(E) IN / NOT IN — membership
SELECT * FROM EMPLOYEE WHERE DeptId IN ('D01', 'D02', 'D04');
SELECT * FROM EMPLOYEE WHERE DeptId NOT IN ('D01', 'D02');
(F) ORDER BY — sort results (ascending by default)
SELECT * FROM EMPLOYEE ORDER BY Salary;        -- ascending
SELECT * FROM EMPLOYEE ORDER BY Salary DESC;   -- descending
(G) NULL handling
SELECT * FROM EMPLOYEE WHERE Bonus IS NULL;
SELECT EName FROM EMPLOYEE WHERE Bonus IS NOT NULL AND DeptID = 'D01';
-- NULL != 0, and NULL combined with arithmetic always gives NULL (5 + NULL = NULL)
(H) LIKE — substring pattern matching
SELECT * FROM EMPLOYEE WHERE Ename LIKE 'K%';     -- starts with K
SELECT * FROM EMPLOYEE WHERE Ename LIKE '%a';      -- ends with a
SELECT * FROM EMPLOYEE WHERE Ename LIKE '_ANYA';   -- exactly 5 chars, ends ANYA
SELECT Ename FROM EMPLOYEE WHERE Ename LIKE '%se%'; -- contains 'se' anywhere
SELECT EName FROM EMPLOYEE WHERE Ename LIKE '_a%';  -- 'a' as 2nd character

-- % = zero, one or many characters      _ = exactly one character

9.7 Data Updation and Deletion

UPDATE — modify existing rows
UPDATE STUDENT SET GUID = 101010101010 WHERE RollNumber = 3;

-- updating more than one column at once:
UPDATE GUARDIAN
SET GAddress = 'WZ-68, Azad Avenue, Bijnour, MP', GPhone = 9010810547
WHERE GUID = 466444444666;
DELETE — remove rows
DELETE FROM STUDENT WHERE RollNumber = 2;
Never skip WHERE

Omit WHERE in an UPDATE and every row's column gets the new value; omit it in a DELETE and the entire table is emptied. Both are explicitly flagged as cautions in the textbook.

9.8 Functions in SQL

Functions are Single Row (Scalar) — one value in, one value out, usable in SELECT/WHERE/ORDER BY — or Aggregate (Multiple Row) — act on a whole group, usable only in SELECT.

(A) Math functions

POWER, ROUND, MOD
SELECT POWER(2,3);          -- 8   (2 to the power 3)
SELECT ROUND(2912.564, 1);  -- 2912.6
SELECT ROUND(283.2);        -- 283  (D=0 rounds to nearest integer)
SELECT MOD(21, 2);          -- 1   (remainder of 21/2)

(B) String functions

UCASE/LCASE, MID, LENGTH, LEFT/RIGHT, INSTR, TRIM family
UCASE("Informatics")           -- INFORMATICS   (also UPPER)
LCASE("Informatics")           -- informatics   (also LOWER)
MID("Informatics", 3, 4)       -- form          (substring: pos 3, length 4)
MID('Informatics', 7)          -- atics         (from pos 7 to the end)
LENGTH("Informatics")          -- 11
LEFT("Computer", 4)            -- Comp
RIGHT("SCIENCE", 3)            -- NCE
INSTR("Informatics", "ma")     -- 6             (position of first match, 0 if absent)
LTRIM(" DELHI")                -- "DELHI"       (strip leading spaces)
RTRIM("PEN ")                  -- "PEN"         (strip trailing spaces)
TRIM(" MADAM ")                -- "MADAM"       (strip both)
TRIM(".com" FROM email)        -- removes a specific substring, not just whitespace

(C) Date functions

NOW, DATE, MONTH(NAME), YEAR, DAY(NAME)
NOW()                       -- current date AND time, e.g. 2026-11-24 19:41:17
DATE(NOW())                 -- just the date part
MONTH("2003-11-28")         -- 11            (numeric month)
MONTHNAME("2003-11-28")     -- November
YEAR("2003-10-03")          -- 2003
DAY("2003-03-24")           -- 24
DAYNAME("2019-07-11")       -- Thursday

Aggregate functions

MAX, MIN, AVG, SUM, COUNT(*), COUNT(column)
SELECT MAX(Price) FROM INVENTORY;
SELECT MIN(Price) FROM INVENTORY;
SELECT AVG(Price) FROM INVENTORY;
SELECT SUM(Price) FROM INVENTORY;
SELECT COUNT(*) FROM EMPLOYEE;                 -- total rows
SELECT COUNT(MEMNAME) FROM MANAGER;             -- counts rows, SKIPPING NULLs
SELECT COUNT(DISTINCT Model) FROM INVENTORY;    -- distinct non-null count
Key exam distinction

Single-row functions return one value per row and work in WHERE/ORDER BY too. Aggregate functions collapse a whole group of rows into one value, and only belong in SELECT (or alongside GROUP BY).

9.9 GROUP BY Clause

Groups rows sharing the same value in a column, so aggregate functions can be applied per group rather than to the whole table. HAVING filters which groups appear in the result (unlike WHERE, which filters individual rows before grouping).

GROUP BY and HAVING
SELECT CustID, COUNT(*) "Number of Cars" FROM SALE GROUP BY CustID;

-- only groups matching a condition on the aggregate itself:
SELECT CustID, COUNT(*) FROM SALE GROUP BY CustID HAVING COUNT(*) > 1;

SELECT PaymentMode, COUNT(PaymentMode) FROM SALE
GROUP BY PaymentMode ORDER BY PaymentMode;

9.10 Operations on Relations

UNION, INTERSECT, MINUS and Cartesian Product are binary operations — both relations need the same number of attributes, with corresponding attributes sharing a domain (except Cartesian Product).

UNION, INTERSECT, MINUS — set operations between two same-shape relations
DANCE ∪ MUSIC   -- UNION: all rows from either table, duplicates shown once
DANCE ∩ MUSIC   -- INTERSECT: only rows present in BOTH tables
DANCE − MUSIC   -- MINUS (set difference): rows in DANCE but NOT in MUSIC
Cartesian Product (X) — every row of table 1 paired with every row of table 2
SELECT * FROM DANCE, MUSIC;
-- degree of result = sum of both degrees
-- cardinality of result = product of both cardinalities
-- e.g. DANCE (degree 3, cardinality 4) x MUSIC (degree 3, cardinality 5)
--      -> result: degree 6, cardinality 20

9.11 Using Two Relations in a Query

A JOIN combines rows from two tables based on a shared/related column — usually a primary key in one, a foreign key in the other — unlike Cartesian Product, which pairs every row with every row regardless of relationship.

Three equivalent ways to write the same join
-- (a) condition in WHERE, with table aliases to disambiguate the shared column
SELECT * FROM UNIFORM U, COST C WHERE U.UCode = C.UCode;

-- (b) explicit JOIN ... ON
SELECT * FROM UNIFORM U JOIN COST C ON U.UCode = C.UCode;

-- (c) NATURAL JOIN -- same result as (a)/(b) but drops the duplicate UCode column
SELECT * FROM UNIFORM NATURAL JOIN COST;
N tables need N−1 joins

Joining 2 tables on equality needs 1 JOIN/NATURAL JOIN; 3 tables need 2; in general, N tables need N−1 joins to connect them all on equality conditions.

10. Exercise (from the textbook — selected highlights)

NCERT Exercise, Chapter 9 (the full textbook exercise has 8 large practical questions — these are a representative subset)

Work through these on a real MySQL install

  1. Define RDBMS and name two RDBMS. Explain ORDER BY and GROUP BY. Differentiate single-row vs. aggregate functions, and ALTER vs. UPDATE, and DELETE vs. DROP.
  2. Predict the output of:
    quick checks
    SELECT POW(2,3);
SELECT ROUND(342.9234,-1);
SELECT LENGTH("Informatics Practices");
SELECT YEAR("1979/11/26"), MONTH("1979/11/26"), DAY("1979/11/26"), MONTHNAME("1979/11/26");
SELECT LEFT("INDIA",3), RIGHT("Computer Science",4), MID("Informatics",3,4), SUBSTR("Practices",3);
  3. Using a MOVIE table (MovieID, MovieName, Category, ReleaseDate, ProductionCost, BusinessCost): display all rows; compute Total_Earning per movie; list distinct categories; compute NetProfit per movie; filter by a cost range; filter by category IN a list; find movies with a NULL ReleaseDate.
  4. Design a Sports database: create a TEAM table (TeamID INT PRIMARY KEY, TeamName VARCHAR with a minimum-length intent) and a MATCH_DETAILS table with foreign keys back to TEAM; insert sample rows into both; describe and query the structure.
  5. Using TEAM + MATCH_DETAILS: find matches where both teams scored >70; find matches where only one team crossed 70; find matches a given team won; rename a table and its columns with ALTER.
  6. Using a SCHOOLUNIFORM database (UNIFORM, COST): add a new item consistently across both tables; add a foreign-key constraint so COST can't reference a UCode missing from UNIFORM; add a CHECK-style constraint so price is always > 0.
  7. Using a Product table (PCode, PName, UPrice, Manufacturer): create it with appropriate types/constraints; order results with a tie-break column; add and populate a Discount column conditionally; apply a percentage increase to one manufacturer's prices; group and count by manufacturer; predict GROUP BY query outputs.
  8. Using the CARSHOWROOM database from this chapter: add a Discount column to INVENTORY with model-dependent values via conditional UPDATEs; find the costliest Petrol car; compute average/total discount for one car model; count cars with zero discount.
