Chapter 1: Exception Handling in Python

Based on NCERT's Class XII Computer Science textbook. This chapter covers what happens when a syntactically correct Python program still fails at runtime — the difference between syntax errors and exceptions, the standard built-in exceptions you'll meet again and again, how to deliberately raise one with raise or assert, and the full try/except/else/finally toolkit for handling them gracefully.

Chapter 1 of 13 NCERT pp. 1–18 ~2–3 Hours Exercise Included

By the end of this chapter, you'll be able to

  • Tell a syntax error apart from a runtime exception, and name the common built-in exceptions
  • Deliberately raise exceptions using raise and assert
  • Write a complete try/except/else/finally block, including multiple except clauses

1.1 Introduction

Sometimes while executing a Python program, the program does not execute at all, or it executes but generates unexpected output or behaves abnormally. These occur when there are syntax errors, runtime errors or logical errors in the code. In Python, exceptions are errors that get triggered automatically. However, exceptions can also be forcefully triggered and handled through program code.

1.2 Syntax Errors

Syntax errors are detected when we have not followed the rules of the Python language while writing a program — they are also called parsing errors. On encountering a syntax error, the interpreter does not execute the program at all until the error is rectified, saved and rerun.

Python shell
>>> marks = 10
>>> if marks > 20:
        print "GOOD SCORE"

SyntaxError: Missing parentheses in call to 'print'. Did you mean print("GOOD SCORE")?

A syntax error is reported with the name of the error and a brief description to help you rectify it — whether you're working in shell mode or running a saved script.

1.3 Exceptions

Even if a statement or expression is syntactically correct, an error can still arise while it executes — trying to open a file that does not exist, dividing by zero, and so on. Such errors are called exceptions.

An exception is a Python object that represents an error. When an error occurs during execution, the exception is said to have been raised. The programmer anticipates such situations and includes code to handle them so the program doesn't terminate abnormally.

Exam point

SyntaxError is itself an exception — but every other exception type only ever occurs when the program is syntactically correct to begin with. A common exam question asks you to justify exactly this.

1.4 Built-in Exceptions

Python's standard library ships an extensive set of built-in exceptions for commonly occurring errors. When one is raised, the appropriate handler code runs and displays the reason along with the exception's name.

Table 1.1 — common built-in exceptions
SyntaxError        Error in the syntax of the Python code
ValueError         Right data type, but an inappropriate/mismatched value
IOError            The file specified cannot be opened
KeyboardInterrupt  User hits Delete/Esc during execution
ImportError        The requested module definition is not found
EOFError           End of file reached without input() reading any data
ZeroDivisionError  Denominator in a division operation is zero
IndexError         Index/subscript in a sequence is out of range
NameError          A local or global variable name is not defined
IndentationError   Incorrect indentation in the program code
TypeError          An operator is supplied a value of the wrong data type
OverFlowError      Result of a calculation exceeds the numeric type's limit
Python shell
>>> print(50/0)
ZeroDivisionError: division by zero

>>> print(var+40)
NameError: name 'var' is not defined

>>> 10+'5'
TypeError: unsupported operand type(s) for +: 'int' and 'str'

A programmer can also create custom exceptions for their own requirements — these are called user-defined exceptions.

1.5 Raising Exceptions

Each time an error is detected, the Python interpreter raises (throws) an exception. Programmers can also forcefully raise exceptions using the raise and assert statements. Once raised, no further statement in the current block executes — control jumps straight to the exception handler.

1.5.1 The raise statement

syntax
raise exception-name[(optional argument)]
Python shell
>>> raise Exception("OOPS!! An Exception has occurred")
Traceback (most recent call last):
Exception: OOPS!! An Exception has occurred

The error raised may be built-in or user-defined. Python also prints a stack traceback — a structured block of text describing the sequence of calls in which the exception occurred.

1.5.2 The assert statement

An assert statement tests an expression; if it evaluates to false, an AssertionError is raised. It's commonly used at the start of a function, or after a function call, to validate input.

assert_example.py
print("use of assert statement")

def negativecheck(number):
    assert(number >= 0), "OOPS... Negative Number"
    print(number*number)

print(negativecheck(100))
print(negativecheck(-350))
# -350 fails the assertion:
# AssertionError: OOPS... Negative Number

1.6 Handling Exceptions

Every exception has to be handled by the programmer to prevent the program from crashing abruptly — writing the extra code that gives a proper message or instruction when an exception occurs is called exception handling.

1.6.2 How handling works

When an error occurs, Python creates an exception object holding information about the error — its type, file name, and position. Handing this object over to the runtime system is called throwing the exception. The runtime searches the call stack in reverse order for a matching handler; when one is found and executed, that's called catching the exception. If no handler is found anywhere in the call stack, the program terminates.

1.6.3 Catching exceptions — try/except

syntax
try:
    # program statements where exceptions might occur
except [exception-name]:
    # code for exception handling if exception-name occurs
Program 1-2
print("Practicing for try block")
try:
    numerator = 50
    denom = int(input("Enter the denominator"))
    quotient = (numerator/denom)
    print(quotient)
    print("Division performed successfully")
except ZeroDivisionError:
    print("Denominator as ZERO.... not allowed")
print("OUTSIDE try..except block")

If denom is non-zero, the except clause is skipped entirely and the quotient prints normally. If denom is 0, execution of the try block stops immediately and control shifts to the matching except block.

Multiple except clauses

A single try block can be followed by several except clauses, each handling a different exception type:

Program 1-3
try:
    numerator = 50
    denom = int(input("Enter the denominator: "))
    print(numerator/denom)
    print("Division performed successfully")
except ZeroDivisionError:
    print("Denominator as ZERO is not allowed")
except ValueError:
    print("Only INTEGERS should be entered")

A bare except: clause (no exception named) can be added last to catch anything not matched by an earlier, more specific clause:

Program 1-4
try:
    numerator = 50
    denom = int(input("Enter the denominator"))
    quotient = (numerator/denom)
    print("Division performed successfully")
except ValueError:
    print("Only INTEGERS should be entered")
except:
    print("OOPS.....SOME EXCEPTION RAISED")

1.6.4 try...except...else

An optional else clause runs only when no exception was raised in the try block:

Program 1-5
try:
    numerator = 50
    denom = int(input("Enter the denominator: "))
    quotient = (numerator/denom)
except ZeroDivisionError:
    print("Denominator as ZERO is not allowed")
except ValueError:
    print("Only INTEGERS should be entered")
else:
    print("The result of division operation is ", quotient)

1.7 Finally Clause

The try statement can also have an optional finally clause. Statements inside finally run regardless of whether an exception occurred — it's commonly used to guarantee a file object gets closed. If used, finally must come last, after every except and the else block.

Program 1-6
try:
    numerator = 50
    denom = int(input("Enter the denominator: "))
    quotient = (numerator/denom)
except ZeroDivisionError:
    print("Denominator as ZERO is not allowed")
except ValueError:
    print("Only INTEGERS should be entered")
else:
    print("The result of division operation is ", quotient)
finally:
    print("OVER AND OUT")

1.7.1 Recovering and continuing with finally

If the exception that occurs doesn't match any except clause present, the finally block still executes first — and only then is the unhandled exception re-raised. Unlike except, finally does not itself terminate the exception.

Program 1-7 — only a ZeroDivisionError handler exists
try:
    numerator = 50
    denom = int(input("Enter the denominator"))
    quotient = (numerator/denom)
except ZeroDivisionError:
    print("Denominator as ZERO is not allowed")
else:
    print("The result of division operation is ", quotient)
finally:
    print("OVER AND OUT")

# Entering non-numeric input (e.g. "var") raises a ValueError,
# which has no handler here:
# OVER AND OUT              <- finally still runs first
# ValueError: invalid literal for int() with base 10: 'var'   <- then re-raised
Chapter summary

Code with a possibility of error goes in try. Each except clause handles one matching exception type raised inside it. The optional else runs only when nothing went wrong. The optional finally runs no matter what, and is placed last.
