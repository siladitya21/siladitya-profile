Chapter 2: Encoding Schemes and Number System

Based on NCERT's Class XI Computer Science textbook. Every key you press is internally mapped to a code, then converted to binary — this chapter covers how (ASCII, ISCII, Unicode), then builds up the four number systems computers work with (binary, octal, decimal, hexadecimal) and every conversion between them, including numbers with a fractional part.

Chapter 2 of 11 NCERT pp. 27–44 ~3 Hours Exercise Included

By the end of this chapter, you'll be able to

  • Explain ASCII, ISCII and Unicode, and why Unicode replaced earlier schemes
  • Convert any whole number between binary, octal, decimal and hexadecimal
  • Convert numbers WITH a fractional part between number systems

2.1 Introduction to Encoding

The computer understands only binary (0/1). When key 'A' is pressed, it's internally mapped to a code value (decimal 65), then converted to binary (0100 0001). Encoding is the mechanism of converting data into an equivalent cipher using a specific code.

2.1.1 ASCII — American Standard Code for Information Interchange
Developed in the early 1960s to standardise character representation.
7-bit ASCII: 2^7 = 128 characters -- English keyboard only.

ASCII value of D = 68 -> binary 1000100
ASCII value of A = 65 -> binary 1000001
ASCII value of T = 84 -> binary 1010100
(so "DATA" encodes as 68 65 84 65, in binary 1000100 1000001 1010100 1000001)
2.1.2 ISCII — Indian Script Code for Information Interchange
Developed in India, mid-1980s. 8-bit code = 2^8 = 256 characters.
Retains all 128 ASCII codes; uses the remaining 128 (160-255) for
the 'aksharas' of Indian languages.
2.1.3 UNICODE — the universal standard
Different encoding schemes couldn't talk to each other -- text made
with one wasn't recognised on a machine using a different one.
UNICODE gives a unique number to EVERY character of EVERY written
language, regardless of device, OS or application.

Common encodings: UTF-8, UTF-16, UTF-32
It is a SUPERSET of ASCII -- values 0-128 are identical to ASCII.
Exam point

'अ' on a Hindi keyboard maps to hexadecimal 0905 (binary 0000100100000101) under Unicode's Devanagari block — a concrete cross-reference between encoding and the number systems covered next.

2.2 Number System

A number system is a method to represent numbers. The count of unique symbols it uses is called its radix or base. Number systems are positional — each symbol's value depends on its position. The rightmost integer-part position is 0, increasing leftward; the first fractional position is −1, decreasing rightward.

Table — the four number systems used in computing
Binary       Base 2,  digits: 0,1
Octal        Base 8,  digits: 0-7
Decimal      Base 10, digits: 0-9
Hexadecimal  Base 16, digits: 0-9, A-F  (A=10, B=11, ... F=15)
Positional value example — (123.45)₁₀
Digit:            1      2      3    .   4      5
Position:         2      1      0        -1     -2
Positional value: 10^2   10^1   10^0     10^-1  10^-2

1x10^2 + 2x10^1 + 3x10^0 + 4x10^-1 + 5x10^-2 = (123.45)10

Binary maps directly to a transistor's ON/OFF (high/low) state. Octal (base 8 = 2³) and hexadecimal (base 16 = 2⁴) exist purely to compactly represent long binary numbers — 3 bits always map to exactly one octal digit, 4 bits to exactly one hex digit.

2.2.5 — Why hexadecimal shows up constantly
MEMORY ADDRESSES: a 16-bit address like 1100000011110001
  is C0F1 in hex -- far easier to remember than 16 raw bits.

COLOUR CODES (RGB, web design): 24-bit colour (8 bits each for
  Red/Green/Blue) is written compactly in hex.
  RED   = 11111111,00000000,00000000  ->  (FF,00,00)
  WHITE = 11111111,11111111,11111111  ->  (FF,FF,FF)
  GREY  = 10000000,10000000,10000000  ->  (80,80,80)

2.3.1 Conversion from Decimal to Other Number Systems

The universal 4-step method (divide by the base)
Step 1: Divide the number by the target base (b)
Step 2: Note the remainder
Step 3: Keep dividing the quotient by b, noting each remainder,
        until the quotient is 0
Step 4: Read the remainders BOTTOM TO TOP -- that's your answer
Example 2.3 — (122)₁₀ to binary (divide by 2)
2 | 122           2 | 15   r=7
2 |  61   r=0      2 |  7   r=1
2 |  30   r=1      2 |  3   r=1
2 |  15   r=0      2 |  1   r=1
...                      0   r=1
(122)10 = (1111010)2       (122)10 = (172)8  [base 8]
Example 2.5 — (122)₁₀ to hexadecimal (divide by 16)
16 | 122
16 |   7   remainder A  (10 in hex is 'A')
         0   remainder 7

(122)10 = (7A)16

2.3.2 Conversion from Other Number Systems to Decimal

The universal method (multiply by positional value, sum)
Step 1: Write the position number of each digit (0, 1, 2... from
        the right)
Step 2: Positional value = base^position
Step 3: Multiply each digit by its positional value
Step 4: Add them all up
Example 2.6 — (1101)₂ to decimal
1x2^3 + 1x2^2 + 0x2^1 + 1x2^0 = 8+4+0+1 = (13)10
Example 2.8 — (3A5)₁₆ to decimal (A = 10)
3x16^2 + 10x16^1 + 5x16^0 = 768+160+5 = (933)10

2.3.3 Binary ↔ Octal/Hexadecimal (the shortcut both ways)

Because 8 = 2³ and 16 = 2⁴, this conversion skips decimal entirely — just group bits.

Example 2.9 — binary → octal (group in 3s, right to left)
(10101100)2  ->  010 101 100  ->  2   5   4
Therefore (10101100)2 = (254)8
Example 2.11 — binary → hex (group in 4s, right to left)
(0110101100)2 -> 0001 1010 1100 -> 1   A   C
Therefore (0110101100)2 = (1AC)16
Reverse direction: each octal/hex digit → fixed-width binary group
(705)8: 7->111, 0->000, 5->101  =>  (705)8 = (111000101)2
(23D)16: 2->0010, 3->0011, D->1101 => (23D)16 = (001000111101)2

2.3.4 Conversion of a Number with Fractional Part

Decimal fraction → other base (MULTIPLY, not divide)
Repeatedly MULTIPLY the fractional part by the target base.
Take the INTEGER part produced each time, top to bottom, as the answer.
Stop when the fraction reaches 0, or starts repeating.

Example 2.14 -- (0.675)10 to binary:
0.675x2=1.350 -> 1    0.400x2=0.800 -> 1   (then .400 repeats -- STOP)
0.350x2=0.700 -> 0    0.800x2=1.600 -> 1
0.700x2=1.400 -> 1    0.600x2=1.200 -> 1
0.400x2=0.800 -> 0    0.200x2=0.400 -> 0

(0.675)10 = (0.1010110)2
Non-decimal fraction → decimal (same positional method, negative exponents)
Example 2.17 -- (100101.101)2 to decimal:
Integer: 1x2^5+0x2^4+0x2^3+1x2^2+0x2^1+1x2^0 = 32+0+0+4+0+1 = 37
Fraction: 1x2^-1+0x2^-2+1x2^-3 = 0.5+0+0.125 = 0.625

(100101.101)2 = (37.625)10
Fractional binary → octal/hex (group each side of the point separately)
Example 2.19 -- (10101100.01011)2 to octal:
Integer: group right-to-left: 010 101 100 -> 2 5 4
Fraction: group LEFT-TO-RIGHT, pad with 0s: 010 110 -> 2 6

(10101100.01011)2 = (254.26)8

7. Exercise (from the textbook)

NCERT Exercise, Chapter 2

Work through these on paper

  1. Write the base values of binary, octal and hexadecimal number systems. Give the full forms of ASCII and ISCII.
  2. Convert: (514)₈ to decimal; (220)₈ to binary; (76F)₁₆ to decimal; (4D9)₁₆ to decimal; (11001010)₂ to decimal; (1010111)₂ to decimal.
  3. Convert these decimals to binary/octal/hexadecimal: (54)₁₀, (120)₁₀, (76)₁₀ to octal, (889)₁₀ to octal, (789)₁₀ to hex, (108)₁₀ to hex.
  4. Express these octal numbers as decimal: 145, 6760, 455, 10.75.
  5. Express these decimals as hexadecimal: 548, 4052, 58, 100.25.
  6. Express these hexadecimal numbers as decimal: 4A2, 9E1A, 6BD, 6C.34.
  7. Convert these binary numbers to octal and hexadecimal: 1110001000, 110110101, 1010100, 1010.1001.
  8. Write the binary equivalent of these octal numbers: 2306, 5610, 742, 65.203.
  9. Write the binary representation of these hexadecimal numbers: 4026, BCA1, 98E, 132.45.
  10. How does the computer understand these texts (hint: 7-bit ASCII code)? (i) HOTS (ii) Main (iii) CaSe
  11. Let X be a number system with B symbols only — write down its base value.
  12. What is the advantage of preparing digital content in an Indian language using a UNICODE font? Encode the word 'COMPUTER' using ASCII and convert it to binary.
