Week 7: Data Collection — APIs & Web Scraping

Course datasets arrive clean and ready. Real projects often start with "the data doesn't exist yet — go get it." This week you learn to collect data from REST APIs and web pages, politely and reliably, and to validate it before it ever reaches an analysis.

Phase 3 of 4 Week 7 of 10 ~3–4 Hours Hands-on Exercise Included

By the end of this week, you'll be able to

  • Fetch, paginate and flatten JSON data from REST APIs
  • Scrape structured data from HTML pages responsibly
  • Validate and store collected data so it can be trusted and reused

1. Calling REST APIs with requests

An API returns structured data (usually JSON) on request. Always prefer an official API over scraping: it's faster, more stable, and explicitly permitted.

api_basics.py
import requests

resp = requests.get(
    "https://api.github.com/repos/pandas-dev/pandas/issues",
    params={"state": "closed", "per_page": 100},
    headers={"Accept": "application/vnd.github+json"},
    timeout=10,
)
resp.raise_for_status()          # turn 4xx/5xx into an exception
issues = resp.json()             # list of dicts
print(len(issues), issues[0]["title"])

Nested JSON doesn't fit neatly into a table. pd.json_normalize flattens nested objects into dotted column names:

flatten.py
import pandas as pd

df = pd.json_normalize(issues)
df = df[["number", "title", "user.login", "created_at", "closed_at", "comments"]]
df["created_at"] = pd.to_datetime(df["created_at"])
df["closed_at"] = pd.to_datetime(df["closed_at"])
df["days_open"] = (df["closed_at"] - df["created_at"]).dt.days
Keep secrets out of code

APIs that need a key should read it from an environment variable — os.environ["API_KEY"] — never from a string committed to Git.

2. Pagination, Rate Limits & Retries

APIs return results in pages, and limit how fast you may call them. A robust collector loops through pages, waits when told to, and retries transient failures.

collector.py
import time
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

session = requests.Session()
session.mount("https://", HTTPAdapter(max_retries=Retry(
    total=5, backoff_factor=1,
    status_forcelist=[429, 500, 502, 503, 504],
)))

def fetch_all(url, params, max_pages=20):
    rows = []
    for page in range(1, max_pages + 1):
        resp = session.get(url, params={**params, "page": page}, timeout=10)
        resp.raise_for_status()
        batch = resp.json()
        if not batch:            # empty page -> no more data
            break
        rows.extend(batch)
        time.sleep(1)            # be polite between requests
    return rows

backoff_factor=1 makes retries wait progressively longer (1s, 2s, 4s…), which is what a server returning 429 Too Many Requests wants from you.

3. Scraping HTML with BeautifulSoup

When there's no API, you can parse the HTML a page returns. Inspect the page in your browser's developer tools, find the elements that hold the data, then select them with CSS selectors.

scrape_books.py
import requests
from bs4 import BeautifulSoup

# books.toscrape.com is a sandbox site built for scraping practice
url = "https://books.toscrape.com/catalogue/page-1.html"
soup = BeautifulSoup(requests.get(url, timeout=10).text, "html.parser")

books = []
for card in soup.select("article.product_pod"):
    books.append({
        "title": card.h3.a["title"],
        "price": float(card.select_one(".price_color").text.lstrip("£Â")),
        "rating": card.select_one(".star-rating")["class"][1],   # e.g. "Three"
        "in_stock": "In stock" in card.select_one(".availability").text,
    })

Scraping responsibly:

  • Check the site's terms of service and robots.txt; don't scrape where it's prohibited.
  • Identify your client honestly with a User-Agent header, and rate-limit yourself.
  • Don't collect personal data you have no lawful reason to hold.
  • Cache pages locally while developing so you don't re-download them on every run.
JavaScript-rendered pages

If the data isn't in the HTML that requests receives, the page builds it in the browser. Look in the Network tab for the JSON request the page makes — calling that endpoint directly is usually simpler than driving a headless browser.

4. Validating & Storing What You Collect

Collected data is untrusted until checked. Write the checks down as code so every new batch is validated the same way.

validate.py
def validate(df):
    problems = []
    if df["title"].isna().any():
        problems.append("missing titles")
    if df.duplicated(subset=["title"]).any():
        problems.append(f"{df.duplicated(subset=['title']).sum()} duplicate titles")
    if not df["price"].between(0, 1000).all():
        problems.append("price out of expected range")
    return problems

issues = validate(books_df)
assert not issues, issues

# Parquet keeps dtypes and is far smaller/faster than CSV
books_df.to_parquet("books_2026-11-13.parquet", index=False)

Put the collection date in the filename (or a column). Websites change; a dated snapshot makes your analysis reproducible even after the source moves on.

  2. Flatten them with json_normalize and compute days_open for each issue.
  3. Scrape all 50 pages of books.toscrape.com (title, price, rating, availability), with a one-second delay between pages.

6. Knowledge Check

4 quick questions. Expand each to check your answer.

Q1

Why prefer an official API over scraping the same site?

APIs return structured data designed to be consumed by programs, are documented, change less often, and are explicitly permitted. Scraped HTML can break whenever the page layout changes and may violate the site's terms.

Q2

What does an HTTP 429 response mean, and how should a collector react?

"Too Many Requests" — you hit a rate limit. Wait and retry with increasing delays (exponential backoff), honoring a Retry-After header if the server sends one, and slow your request rate going forward.

Q3

What does pd.json_normalize do?

It flattens nested JSON objects into a flat table, turning nested keys into dotted column names such as user.login, so API results can be analyzed like any other DataFrame.

Q4

Why save collected data with a date in the filename or a column?

Online sources change over time. A dated snapshot records exactly what you analyzed, so the analysis can be reproduced and differences between collection runs can be explained.
